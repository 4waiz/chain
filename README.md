# Chain Reaction City

**One tap. Total chaos.**

A one-touch 3D physics puzzle game for Android. Each level is a miniature toy
diorama: study it, tap one starting object, and watch the chain reaction play
out. Built in Flutter with an in-repo 3D renderer and an in-repo deterministic
physics engine — no native dependencies, no game engine.

`logo.png` is the art bible. Every colour, proportion and material in the game
derives from it.

JDK 17 · Blender 5.2 LTS.

```bash
flutter pub get
flutter run
```

```bash
flutter build apk --release
```

## How it is put together

```
lib/
  engine/            no gameplay knowledge — reusable 3D + physics
    render/          mesh, GLB loader, camera, flat-shaded rasteriser
    physics/         bodies, narrowphase, deterministic solver
    assets/          model cache
  game/
    level/           level schema, loader, validator, procedural generator
    play/            runtime, devices, reaction tracker, camera director, FX
    ui/              design system and every screen
  data/              save, settings, audio
tools/
  blender/           every model in the game, as Python
  levels/            every level in the game, as Python
  make_audio.py      every sound in the game, synthesised
assets/
  models/            172 exported .glb files
  levels/            level JSON + campaign index
  audio/             28 .wav files + music loop
art/blender/         .blend sources
docs/                design, pipeline, decisions, limitations
```

### The renderer

The art direction is untextured, flat-shaded, solid-colour low-poly — so a face
needs exactly one colour, which means the **entire scene can be transformed and
lit on the CPU into one vertex buffer and submitted as a single `drawVertices`
call per frame**. Depth sorting is an O(n) counting sort. Contact shadows are
projected bounding boxes, hulled in screen space and blurred.

Measured on an Android 16 emulator, release build: 3,134 triangles at
**p50 0.41 ms** of renderer CPU; 50,334 triangles at **p50 6.98 ms**.

`flutter_scene` and `three_js` were both installed and build-tested first. The
reasoning and the evidence are in
[docs/renderer_decision.md](docs/renderer_decision.md).

### The physics

Fixed 1/240 s step, sequential impulses, warm-started contacts, split-impulse
position correction, island sleeping, sphere and oriented-box colliders.

Determinism is structural rather than incidental: fixed substep, bodies
iterated in index order, contact pairs generated in sorted order, warm-start
impulses matched by feature id, no hash-order iteration and no RNG anywhere in
the step. `test/physics_test.dart` asserts that two identical setups produce
**bit-identical** results and that variable frame pacing changes nothing.

### The content pipeline

Nothing in `assets/` is hand-authored. Delete `assets/models/`,
`assets/audio/`, `assets/levels/` and the Android icons, re-run four scripts,
and you get the same bytes back:

```bash
python tools/make_audio.py
```

```bash
python tools/make_android_assets.py
```

```bash
python tools/levels/build_all.py
```

```bash
python tools/make_asset_manifest.py
```

Models are built through Blender's Python API from `tools/blender/` — see
[docs/blender_pipeline.md](docs/blender_pipeline.md).
