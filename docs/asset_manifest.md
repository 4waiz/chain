# Asset manifest

Every model in the game is generated by code in `tools/blender/` and exported to `assets/models/` as binary glTF. Delete `assets/models/` and re-run the three build scripts and you get the same geometry back — there are no hand-edited files in the pipeline.

This document is generated by `tools/make_asset_manifest.py` from the export manifests the Blender scripts write, so it cannot drift from what was actually exported.

## Export settings

All models are exported with the same glTF settings, set in `tools/blender/toykit.py`:

- **Format** — GLB (binary glTF 2.0), one file per asset
- **Scale** — metric, 1 unit = 1 metre; toys are 0.05–1.2 m
- **Transforms** — applied; every object's pivot is at its bounding-box centre so mesh and physics body agree
- **Orientation** — Y-up conversion on; assets that have a forward face +X
- **Materials** — exported as flat `baseColorFactor` only
- **Normals, UVs, tangents, skins, morphs, animations, cameras, lights** — all off. The renderer shades per face from geometry, so normals in the file would be dead weight
- **Shared accessors** — on


## Colliders

The `collider` column is the shape the runtime uses, not extra geometry in the file. `box` derives an oriented box from the model's bounding box; `sphere` uses the recorded radius; `cylinder` is approximated by a box; `none` means the model is visual only. A level can override any of these with an explicit `size` or `radius`.
